# 포토미션 verify 평가 기록

verify(사진 판정)를 어떤 평가셋으로, 어떤 모델로 재고, 그 결과로 무엇을 정했는지 모은 기록이다.
정답은 [정답 판단 기준](label_criteria.md)으로 표시했다. 새로 측정할 때마다 측정 이력에 한 줄씩 이어 붙인다.

- 기준일: 2026-10-15
- 사진과 결과 파일은 AI Hub 이용 조건 때문에 레포에 올리지 않고 외장 디스크(T7)에만 둔다. 이 문서에는 숫자와 결정만 적는다.

## 1. 평가셋

| 평가셋 | 사진 | 미션 | 정답 | 주로 재는 것 |
|---|---|---|---|---|
| A 경주 랜드마크 | 첨성대·대릉원·동궁과월지·월정교 각 50장 = 200장 (AI Hub 동부권) | 고정 문구 "OO가 잘 보이게 사진 찍기". 같은 사진에 맞는 장소 미션과 다른 장소 미션을 한 번씩 = 400건 | 사람 표시 | 정답 일치, 치명적 FP(다른 장소) |
| A 닮은 장소 | 월정교·동궁과월지 사진 100장 | 반대 장소 미션 100건 | 모두 실패 (자동) | 치명적 FP(닮은 장소) |
| B 카테고리별 | 5개 지역 × 자연·음식·액티비티·쇼핑 × 20장 = 400장 | 서비스 generate로 만든 실제 미션 | 사람 표시 (실패 74%) | FP(맞는 장소, 미션 안 함) |
| B 보강 | B에서 실패로 표시한 사진 중 카테고리별 50장 | 사진을 보고 쓴 미션 | 사람 표시 172장 | FN(맞게 찍은 사진을 막는지) |

- **개선용(dev)과 최종용(final)을 여행 단위로 60 : 40으로 나눴다** (`eval_split.json`, seed 고정).
  - dev: 개선 실험을 고르고 비교할 때 계속 쓴다.
  - final: 출시 판단 때 출시 후보 하나만 한 번 잰다. 고르는 데 쓰지 않은 사진이라 부풀려지지 않은 숫자다. 측정·집계 스크립트는 `--open-final` 없이 final을 열지 못한다.
  - 여행 단위로 나눈 이유: 같은 여행 사진은 비슷해서, 사진 단위로 나누면 거의 같은 사진이 양쪽에 들어가 final 숫자도 부풀려진다.
- 평가에 쓴 여행(190개)은 학습 데이터에 넣지 않는다.
- 미션 자체가 애매한 건("미션 애매")은 집계에서 뺀다.

## 2. 오류 분류와 출시 기준

Positive = 성공 판정, Negative = 재시도·실패 판정이다.

| 오류 | 정답 → 판정 | 뜻 |
|---|---|---|
| 치명적 FP | 다른·닮은 장소 → 성공 | 엉뚱한 장소 사진을 통과시킴 |
| FP | 실패(맞는 장소, 미션 안 함) → 성공 | 장소는 맞지만 미션을 안 한 사진을 통과시킴 |
| 가벼운 FP | 재시도 → 성공 | 대상이 가려지거나 작은 사진을 통과시킴 |
| 무거운 FN | 성공 → 실패 | 맞게 찍었는데 실패 판정 |
| 가벼운 FN | 성공 → 재시도 | 맞게 찍었는데 다시 찍으라고 함 |

| 지표 | 기준 | 성격 |
|---|---|---|
| 치명적 FP (다른 장소, 닮은 장소 각각) | 10% 이하 | 출시 관문 |
| 무거운 FN | 2% 이하 | 출시 관문 |
| FP | 15% 이하 | 참고 목표 |
| 가벼운 FP | 30% 이하 | 참고 목표 |
| 가벼운 FN | 20% 이하 | 참고 목표 |

- 출시 관문은 final에서 추정값과 신뢰 구간 상한으로 판단한다. dev 성공 사진 134장으로는 무거운 FN 1건(0.8%)도 상한이 3.49%라, 관문 판단에 필요한 사진 수는 따로 정한다.
- 집계: `scripts/eval_cases.py`. 지표마다 그 오류가 생길 수 있는 사진만 분모로 둔다.
- **등급 규칙 변경 (10/16):** 객관식에서 장소 "모름"(Q4 unknown)을 성공에서 재시도로 바꿨다(`question_format.rule_grade`). 모름을 성공으로 두면 모델이 구별하지 못한 닮은 장소 사진이 그대로 통과한다. 실패로 두면 맞는 장소 사진이 무거운 FN이 될 수 있어 재시도로 정했다.
  - 이 규칙은 모델이 "모름"이라고 답한 사진만 막는다. M15처럼 모델이 다른 장소를 "예"라고 답하면 그대로 통과한다. 닮은 장소 FP의 해결책이 아니다.
  - 사람 성공 사진의 재시도율이 늘 수 있다. 재시도가 반복되면 사용자가 미션을 끝내지 못하므로, 이후 측정에서 치명적 FP와 함께 사람 성공 사진의 재시도율을 본다. 재시도 뒤 다시 찍어 성공하는 비율은 서비스 기록이 있어야 잴 수 있다.
  - 이 문서의 M15까지 객관식 숫자는 당시 규칙(모름도 성공)으로 계산한 기록이다. 집계 스크립트(`eval_cases`, `baseline_verify`, `measure_eval_b`, `place_probe`)는 모두 저장된 답에서 지금 규칙으로 등급을 다시 계산하므로, 옛 결과 파일을 다시 집계하면 이 문서의 숫자와 다를 수 있다. 옛 결과 파일은 고치지 않는다.
  - 사람 정답에도 같은 기준을 더했다(`label_criteria.md`). 기존 평가셋 A·B 정답은 이 기준으로 다시 확인하지 않았다.

## 4. 현재 결과 (dev)

dev 595건(A 272 + B 222 + B 보강 101), 재표시 정답 적용·미션 애매 제외. 점수 방식은 성공 90 / 재시도 40, 객관식은 등급 규칙으로 등급을 정했다.

| 지표 | 기준 | Pro 점수 | Qwen 점수 | Qwen 객관식 |
|---|---|---|---|---|
| 치명적 FP 다른 장소 | 10% 이하 | 1.0% | 1.9% | 51.5% |
| 치명적 FP 닮은 장소 | 10% 이하 | 7.8% (4/51) | 13.7% (7/51) | 54.9% (28/51) |
| 무거운 FN | 2% 이하 | 0.5% | 0.5% | 3.3% |
| FP | 15% 이하 | 0.6% | 1.7% | 15.1% |
| 가벼운 FP | 30% 이하 | 14.0% | 7.0% | 43.0% |
| 가벼운 FN | 20% 이하 | 7.6% | 68.3% | 0.0% |
| 정밀도 | – | 90.3% | 76.0% | 55.1% |
| 재현율 | – | 91.8% | 31.1% | 96.7% |
| 평균 지연 | 참고 | 10.9초 | 약 1.9초 | 약 1.5초 |

- Qwen 측정 환경(M11): RunPod Pod H100 80GB, vLLM 0.31.0, `Qwen/Qwen2.5-VL-7B-Instruct` bf16, 최대 길이 8,192, 온도는 모델 기본 설정. 맥에서 서비스와 같은 리사이즈(긴 변 1024)로 한 장씩 보냈다. 응답 실패·형식 오류는 1,254건 중 0건이었다. 지연은 서비스용 서버리스 GPU와 다르다.

### 알게 된 것

- **객관식:** 다른·닮은 장소 사진 169건에 장소 질문(Q4) "아니오"가 0건이었다. 예를 들어 동궁과월지 사진에 월정교 미션을 주면 "월정교가 분명히 보인다", "맞는 장소다"라고 답했다. 막힌 건은 대부분 대상 "없음"(Q2) 때문이었다. "재시도"도 거의 쓰지 않았다(B 340건 중 6건).
- **점수:** 점수를 10점 단위로 주고, 맞는 장소와 다른 장소 사진이 똑같이 70점대에 몰렸다. 90 기준에서 치명적 FP가 낮은 것은 장소를 알아봐서가 아니라 맞는 사진까지 대부분 막아서다.
- **Pro 객관식(M12):** 같은 지시문으로 Pro는 닮은 장소 51건에 "아니오" 37건, 치명적 FP 7.8%였다. 객관식 설계는 유효하고, 문제는 Qwen의 장소 구분 능력이다.
- **기준·규칙 조정(M13):** 점수 방식은 75점과 70점 사이에 절벽이 있다(75 이상이면 가벼운 FN 약 66%, 70이면 치명적 FP 다른 장소 45.6%). 닮은 장소는 95점(아무것도 통과 안 시킴)을 빼면 어떤 기준에서도 13.7% 이상이었다. 객관식은 Q4 "모름"을 재시도·실패로 바꿔도 치명적 FP가 거의 그대로였다.

### 결론

- 제로샷 Qwen2.5-VL-7B는 답 형식과 관계없이 0.5~1km 떨어진 닮은 장소를 구별하지 못한다. 기준 점수나 등급 규칙 조정으로는 출시 관문을 넘을 수 없다.
- 판정 형식은 객관식(질문별 답 + 규칙 등급)을 유지한다.
- 장소 구분은 두 갈래로 푼다.
  - 장소 질문 문구 수정: 목표 장소 이름에 맞추지 말고, "아니오" 기준을 "확신"에서 "특징이 맞지 않음"으로 바꾼 지시문을 dev로 잰다.
  - 학습 데이터에 닮은 장소 어려운 오답을 넣는다. 랜드마크가 미션 대상이면 닮은 장소 사진의 정답은 Q2 "없음" + Q4 "아니오"다.

## 6. 장소 구별 실험 (M15)

**결론:** 목표 장소를 알려 주는 지금 판정은 세 모델 모두 닮은 장소를 과잉 통과시켰다(56.9~96.1%). 목표를 숨긴 장소 식별을 결합하면 치명적 FP는 줄지만 정답 사진의 재시도가 늘었고, 어떤 후보도 출시 관문 통과를 확인하지 못했다.

M11에서 Qwen이 닮은 장소에 장소 "아니오"를 한 번도 하지 않은 원인을 나눠 보려고, 학습 없이 형식·모델만 바꿔 쟀다.

- 표본: dev 닮은 장소 오답 51건(10/13과 같은 사진·미션) + 같은 사진 51장에 맞는 장소 미션 51건. 고유 사진 51장
- 사람 정답(맞는 장소 51장): 성공 26 / 재시도 10 / 실패 15. `gyeongju_labels.json`에 재표시(`relabel_labels.json`)를 우선 적용하고 미션 애매는 뺐다. 닮은 장소 오답의 정답은 항상 실패다
- 환경: RunPod H100, vLLM 0.31.0, bf16, 온도는 모델 기본값, 응답 형식은 json_schema로 강제. Qwen3-VL-8B-Thinking은 `--reasoning-parser deepseek_r1`로 생각과 답을 나눠 받았다.
- 형식(`scripts/place_probe.py`)
  - question: 지금 객관식(목표 장소를 요청에 줌)
  - question_obs: 객관식 앞에 "장소를 알 수 있는 특징" 서술 칸을 먼저 씀
  - identify: 목표를 주지 않고 경주 4곳·기타·모름 중 고름. 사진마다 1번
  - `--logprobs`: 장소 답 자리의 선택지별 토큰 확률

**① 목표 제시형 객관식 (사람 정답 기준)**

| 모델·형식 | 닮은 장소 치명적 FP | 무거운 FN | 가벼운 FN | 가벼운 FP | FP | 시간 중앙 |
|---|---|---|---|---|---|---|
| Qwen2.5 question | 29/51 (56.9%) | 0/26 | 0/26 | 7/10 | 3/15 | 1.6초 |
| Qwen2.5 question_obs | 46/51 (90.2%) | 0/26 | 0/26 | 9/10 | 11/15 | 2.5초 |
| Qwen3-Thinking question | 42/51 (82.4%) | 0/26 | 0/26 | 10/10 | 8/15 | 7.8초 (30초 초과 3/102) |
| Qwen3-Instruct question | 49/51 (96.1%) | 0/26 | 0/26 | 10/10 | 10/15 | 1.9초 |

- 네 경우 모두 이번 표본의 사람 성공 26장에서 FN이 관찰되지 않았고, 관찰된 오류는 과잉 통과였다. 0/26의 단측 95% 상한은 약 10.9%라 무거운 FN 2% 이하의 근거는 아니다.
- 관찰 칸을 넣자 닮은 장소에서 target "없음"이 21→1건으로 줄고, 통과 46건 중 11건은 장소 "모름"이었다. 기존 target 판정이 장소 구별 실패를 최종 등급에서 가리고 있었다. (원인 분리는 아니고, 어떤 칸의 변화가 등급을 바꿨는지 확인한 것이다)
- 장소 "모름"이면 재시도로 바꾸는 규칙에서 닮은 장소 치명적 FP 감소는 question_obs에서만 관찰됐다(46→35/51). 바뀐 15건 중 사람 성공 사진은 0건이었다.
- 확률 기준값: Qwen2.5 question에서 "예" 확률 기준을 올리면 맞는 장소 성공도 같이 줄었다(0.95에서 닮은 장소 25.5%, 모델 성공 판정 37.3%). Qwen3 두 모델은 확률이 거의 1이라 효과가 없었다. 이 결과는 "이 추출 방법(답이 갈리는 첫 토큰의 상위 10개)과 기준값으로는 쓸 만한 지점이 없었다"로만 해석한다.

**② 목표 숨김 식별 (사람 정답 성공 사진에서의 정확도)**

미션 성공 라벨을 장소 식별 가능 여부의 대리 지표로 썼다. 장소 식별 가능 라벨은 따로 없다.

| 모델 | 전체 | 동궁과월지 | 월정교 | 틀린 경우 |
|---|---|---|---|---|
| Qwen2.5 | 12/26 | 10/12 | 2/14 | 모두 다른 장소로 오인 |
| Qwen3-Thinking | 22/26 | 12/12 | 10/14 | 모두 다른 장소로 오인 |
| Qwen3-Instruct | 22/26 | 10/12 | 12/14 | 모두 다른 장소로 오인 |

**③ 객관식 + 장소 식별 결합 (사후 계산)**

기존 실패·재시도는 유지하고, 기존 성공 중 식별 장소가 요청 목표와 다르면 재시도로 바꾼다.

| 모델 | 닮은 장소 치명적 FP | 무거운 FN | 가벼운 FN | 닮은 장소 → 재시도 |
|---|---|---|---|---|
| Qwen2.5 | 7/51 (13.7%) | 0/26 | 14/26 | 23/51 |
| Qwen3-Thinking | 13/51 (25.5%) | 0/26 | 4/26 | 30/51 |
| Qwen3-Instruct | 6/51 (11.8%) | 0/26 | 4/26 | 44/51 |

- 따로 한 두 호출의 결과를 이번 결과를 본 뒤 정한 규칙으로 합친 값이다. 실제 서비스 흐름(후보 목록 생성 → 순서대로 호출)은 재지 않았다.
- Qwen3-Instruct는 치명적 FP가 49/51 → 6/51로 줄었지만, 사람 성공 사진 4/26장이 재시도로 바뀌었다.
- 불일치를 재시도가 아니라 실패로 보내면 이 사람 성공 사진(Qwen3 두 모델 기준 4장, Qwen2.5 기준 14장)이 무거운 FN이 된다. 오류를 없애는 것이 아니라 사용자에게 주는 등급을 바꾸는 선택이다. 두 답이 같이 틀린 치명적 FP(Instruct 6건)는 남는다.
- 닮은 장소 사진 대부분이 실패 대신 재시도를 받는다. 엉뚱한 장소에서 다시 찍게 하는 사용자 경험과 재제출 처리를 따로 정해야 한다.

**한계**

- 표본이 작다. 6/51의 95% 구간은 5.5~23.4%다. 같은 여행 사진이 섞여 있어 실제 불확실성은 더 크다. 무거운 FN 2%를 확인하려면 독립 표본·오류 0건·단측 95% 조건에서도 사람 성공 사진이 최소 149장 필요하다.
- identify는 후보가 경주 4곳 + 기타·모름으로 닫혀 있고, "경주에서 찍었다"는 힌트와 관찰 칸, "안압지" 별칭이 있다. 서비스 장소는 열린 목록이다. 후보 밖 장소로 잘못 본 경우가 이번 계산에서는 막힘으로 셌지만 서비스에서는 통과가 될 수 있다.
- question과 identify는 목표 이름 말고도 지시문·칸·후보가 달라서, "목표를 알려 주면 맞장구친다"는 원인은 분리되지 않았다.
- question_obs 기록은 집계 함수가 받는 형식 이름이 없어 집계 때만 question으로 바꿔 넣었다. 실제 실험 형식은 question_obs다.
- final은 쓰지 않았다.

**정리:** Qwen3-VL-8B-Instruct + 장소 식별 결합이 이번 조합 중 치명적 FP가 가장 낮았다(6/51). 대신 사람 성공 사진 4/26장이 재시도로 바뀌었고, 사후 계산이며 표본이 작아 **출시 관문 통과는 확인하지 못했다.** Qwen3-VL-8B-Instruct는 다음 실험의 우선 후보이며 학습 기반 모델 교체는 아직 결정하지 않았다.

**자기 정답 일치도 (M16, 10/17)**
- 방법: 10/10 재표시 정답(미션 애매 제외 446장)에서 A 20 · B 조건어 미션 20 · B 무작위 10장을 뽑아(seed 고정), 같은 사람이 이전 답을 보지 않고 다시 표시했다. 기준 정답은 성공 18 · 재시도 17 · 실패 15장이다.
- 결과: 42/50 일치(84%), Cohen's kappa 0.76. A 19/20, B 23/30. 실패 15장은 모두 일치했고 성공↔실패로 뒤바뀐 사진은 없다. 달라진 8장 중 7장이 성공↔재시도 사이였다. 50장이라 오차 폭이 크다.
- 달라진 8장은 다시 보고 정답을 정했다. 6장은 기존 정답을 유지했고(기존 기준으로 판단 가능 4장, 새로 더한 기준 2장), 2장을 고쳤다(dev 1장 재시도 → 실패, final 1장 재시도 → 성공). final 1장은 모델 결과를 보기 전에 사진만 보고 고쳤다. 원본은 T7 `relabel_labels.before-self-agreement.json`에 남겼다.
- 기준에 없던 경우 3가지("다 같이"의 일행 여부, 꽃 미션의 억새·갈대, 대상이 둘인 미션에서 핵심 대상 없음)를 `label_criteria.md`에 더했다.
- 이 문서의 이전 dev 숫자는 고치기 전 정답으로 계산했다. 다시 집계하면 dev 1장만큼 달라질 수 있다.

## 8. 다시 재는 법

레포 루트에서 실행한다. 사진·정답·결과는 T7(`/Volumes/T7/aihub`)에 있다. `--dry-run`을 붙이면 호출 없이 호출 수만 확인한다.

```bash
A=/Volumes/T7/aihub; T=$A/278_동부권; R=$A/eval_b/results
Z=$(ls "$T"/Training/*/*/Training/01.원천데이터/TS_photo_2.zip)
M=<모델 이름>; F=<score | question>   # 자체 모델이면 --base-url <서버 주소>/v1 추가

# 평가셋 B · B 보강
uv run python -m scripts.measure_eval_b --aihub $A --set all --format $F \
  --split-file $A/eval_split.json --split dev --model $M --out $R/${M}_${F}_dev_B.jsonl
# 평가셋 A 기본
uv run python -m scripts.baseline_verify --mapping $T/target_photos_training.tsv --photos "$Z" \
  --per-place 50 --format $F --split-file $A/eval_split.json --split dev --model $M \
  --same-as $T/baseline/pro-preview_default.jsonl --out $T/baseline/${M}_${F}_dev_default.jsonl
# 평가셋 A 닮은 장소
uv run python -m scripts.baseline_verify --mapping $T/target_photos_training.tsv --photos "$Z" \
  --per-place 100 --lookalike-only --all-negatives --format $F --split-file $A/eval_split.json --split dev --model $M \
  --same-as $T/baseline/pro-preview_lookalike100.jsonl --out $T/baseline/${M}_${F}_dev_lookalike100.jsonl

# dev 집계 (재표시 정답 적용)
uv run python -m scripts.eval_cases \
  --a $T/baseline/${M}_${F}_dev_default.jsonl --a $T/baseline/${M}_${F}_dev_lookalike100.jsonl \
  --a-labels $A/labeling/gyeongju_labels.json --b $R/${M}_${F}_dev_B.jsonl \
  --relabel $A/relabel/relabel_labels.json --split-file $A/eval_split.json --split dev
```

- `--model`을 빼면 기본값인 Gemini Pro를 유료로 호출하고, `--base-url`을 빼면 맥의 로컬 서버로 간다.
- Pro 기존 결과는 파일 이름이 다르다: B는 `eval_b/results/pro_B.jsonl`·`pro_B_aug.jsonl`, A는 `278_동부권/baseline/pro-preview_default.jsonl`·`pro-preview_lookalike100.jsonl`.
- `--split final`과 `--open-final`은 출시 판단 때만 쓴다.

### 장소 구별 실험 (M15)

평가셋 A 닮은 장소 명령과 같지만 두 가지가 다르다.

- **`--with-positives`가 꼭 필요하다.** 기본 명령은 닮은 장소 오답만 남겨서, 맞는 장소 미션이 빠지고 identify(사진마다 1번, 맞는 장소 케이스로 셈)는 0건이 된다
- `--same-as`는 빼고, 장소 답 확률을 받으려면 `--logprobs`를 붙인다 (OpenAI 호환 서버만)

```bash
P=$T/baseline/probe; mkdir -p $P
F=<question | question_obs | identify>
uv run python -m scripts.baseline_verify --mapping $T/target_photos_training.tsv --photos "$Z" \
  --per-place 100 --lookalike-only --with-positives --all-negatives --logprobs \
  --format $F --split-file $A/eval_split.json --split dev --model $M --base-url <서버 주소>/v1 \
  --out $P/${M}_${F}.jsonl

# 요약 (형식별 통과율, identify 정확도, 확률 기준값별 결과)
uv run python -m scripts.place_probe $P/${M}_${F}.jsonl
```
- 사람 정답 기준 지표와 식별 결합 계산은 레포 스크립트에 아직 없다(M15는 임시 스크립트로 계산).
