# ADR-0003: 장소 선정을 Semantic ID 생성 모델과 후보 제한 디코딩으로 구현

## Status

Proposed

1. Proposed: 2026-10-14

ADR-0005의 최종 평가를 통과하면 Accepted로 바꾸고, 같은 시점에 ADR-0000을 Superseded(by ADR-0003)로 갱신한다.

## Context

**문제**

- ADR-0000의 규칙 선정은 카테고리 점수에 동점이 없으면 지역·카테고리 구성·회피조건이 같을 때 그룹이 달라도 같은 장소를 낸다. 추천 품질의 정량 평가 기준도 없다.
- 현재 규칙 파이프라인은 장소 사이 거리를 보지 않는다. 대표 설문 24개 × 5개 지역에서 잰 연속 장소 거리 중앙값은 서울 7.7km, 부산 7.6km, 경주 5.9km, 전주 3.0km, 제주 25.6km다. 실제 여행 로그의 연속 방문 거리 중앙값은 0.9, 1.7, 1.1, 0.5, 6.0km이고, 같은 지역의 무작위 두 장소 사이는 9.2, 10.3, 5.0, 2.4, 28.1km다.
- ADR-0000이 요구한 대로, LLM 호출을 쓰지 않으면서 규칙을 대체하는 방식을 새 ADR로 정한다.

**조건과 규모 (확인된 사실)**

- 후보 DB는 `ai_places` 10,165건이다. 영업 중, 평점 3.0 초과, 평가 수 10 이상 필터를 적용하면 지역별 후보가 약 57~62% 남고, 이 필터 적용 후 7,680건 조합 테스트가 모두 통과했다.
- 서비스 설문 응답과 행동 로그는 없다. 학습에는 AI-Hub 국내 여행로그를 쓴다. 서비스 5개 지역으로 한정하면 학습 가능한 하루 시퀀스는 12,870개(여행 5,828건), 학습 문제는 45,146개다.
- 로그 방문지와 DB 장소를 이름·좌표로 대응시킬 수 있는 비율은 서비스 지역 방문 64,336건 중 엄격 기준 17.5%, 완화 기준 34.0%다. 방문지의 POI_ID는 37.8%만 채워져 있다.
- 서버 호스트는 2 vCPU, 메모리 3.8GB(여유 약 2.5GB)다.

**가정 (확인되지 않음)**

- 개인 여행자의 취향으로 학습한 모델이 그룹 점수(그룹 취향 상위 2개 카테고리)를 입력해도 작동한다. 데이터에 그룹 취향 정보가 없어 직접 검증할 수 없다.
- 약 1,000만 파라미터대의 소형 트랜스포머를 처음부터 학습해도 학습 규모(4.5만 문제)에서 과소·과적합이 심하지 않다. 참고한 TIGER 논문의 데이터(약 20만 상호작용 추정)보다 작다.
- 여행 미션 코드가 참가자의 사전 선호를 반영한다. 선택형인지 과제로 주어진 것인지 문서에서 확인하지 못했다.

## Decision

우리는 v1 trips의 장소 선정을 Semantic ID 시퀀스 생성 모델로 구현하고, 하드 제약은 디코딩 후보 제한으로 남긴다.

- 아이템 표현: 정규화한 이름과 시도·시군구를 오픈 임베딩 모델로 임베딩하고 RQ-VAE(3단계 × 코드북 256, 충돌 시 구분 코드)로 코드를 부여한다. 카테고리 라벨은 임베딩 텍스트에 넣지 않는다. 양자화기는 DB 장소만으로 학습한다.
- 모델: 소형 트랜스포머를 처음부터 학습한다. 입력은 시작 토큰, 카테고리 4개의 0/1 취향 토큰, 지역 토큰이다. 첫 장소도 모델이 생성한다.
- 디코딩: 후보 제한을 적용한 결정론 빔 서치로 슬롯을 순서대로 채운다. 후보 제한은 지역, 회피조건, 영업·평점·평가 수 하한, 이미 쓴 장소, 2·5번째 슬롯 FOOD, 6번째 슬롯 야간형(문항 10 그룹 점수 3 초과 시)이다.
- 규칙으로 채우는 혼합 구조는 최후순위 대안으로만 둔다.
- 장소 사이 거리는 v1에서 입력으로 넣지 않고 평가 지표(연속 거리)로 측정한다. 기준에 못 미치면 디코딩에 반경 제한을 추가한다.

## Alternative / Considered Options

### 1. 규칙 기반 유지 (ADR-0000)

- (장점) 재현성과 테스트가 이미 갖춰져 있고 운영 중이다.
- (단점) 같은 입력에 같은 장소를 내고 거리를 보지 않으며 품질 지표가 없다.
- (소결) 대체 후보로 평가해서 판단한다. 평가 전에는 유지하며, 기준선으로 남긴다.

### 2. NAIS, FIAN (장소 ID 임베딩 협업 필터링)

- (장점) 추천 시스템의 대표적인 어텐션 기반 방식이다.
- (단점) 아이템 ID 임베딩이 필요한데 로그와 DB 장소의 대응이 17.5~34%에 그친다. 순서가 있는 하루 일정을 생성하지 못하고 그룹 점수 입력 구조가 아니다.
- (소결) 선택하지 않았다.

### 3. SAINT, CatBoost 점별 회귀 (정형 데이터 지도학습)

- (장점) 가볍고 AI-Hub 모델 설명에서 쓰인 방식이다.
- (단점) (사용자, 장소) → 만족도를 예측하는 점수 모델이라 순서 있는 일정과 슬롯 구조를 만들지 못한다.
- (소결) 모델로는 선택하지 않고, 평가의 기준선으로 쓴다.

### 4. 위치 격자 토큰을 Semantic ID에 포함

- (장점) 이동 패턴을 모델이 학습한다. 실제 연속 방문이 같은 격자 안인 비율은 서울 63%, 부산 49%, 경주 67%, 전주 74%, 제주 45%다.
- (단점) 격자 지름(약 5.8km)이 연속 방문 거리 중앙값(0.5~1.7km)보다 거칠고, 로그가 적은 격자는 학습이 부족하다. 거리를 보장하지 못하고 ID가 4토큰에서 5토큰으로 늘어난다.
- (소결) v1에서는 선택하지 않고, 평가에서 거리가 미달할 때 반경 제한을 우선 검토한다.

### 5. 사전학습 모델을 백본으로 사용

- (장점) 학습 규모가 작을 때 안정적일 수 있다.
- (단점) Semantic ID 코드는 사전학습된 모델이 본 적 없는 새 토큰이어서 이점이 그대로 넘어오지 않는다. 임베딩 단계가 이미 사전학습 모델을 쓴다.
- (소결) 선택하지 않았다. 처음부터 학습이 부족하거나 과적합이 심하면 재검토한다.

### 6. 카테고리 라벨을 임베딩 텍스트에 포함

- (장점) 이름만으로 종류를 알 수 없는 장소("온담", "스타벅스")의 종류를 알려 줄 수 있다.
- (단점) 정렬 실험(2026-10-16)에서 정답 쌍의 32%가 한쪽에만 라벨이 있거나(로그의 31%는 유형 코드에 라벨이 없음) 구성이 달라(DB는 여러 카테고리 가능) 텍스트가 같을 수 없었고, 그 쌍의 코드 일치율은 1~4%였다. 같은 방문 7,439건 기준으로 라벨을 넣으면 첫 코드 일치율이 BGE-M3는 93.0%에서 78.3%로, Qwen3는 90.7%에서 82.0%로 떨어졌고 검색 성공률(방문 가중 top1 94.7%)은 달라지지 않았다.
- (소결) 선택하지 않았다. 카테고리는 디코딩의 후보 제한(점심·저녁 FOOD)에서 DB의 `ai_place_categories`로 따로 쓴다.

## Consequences

### Positive (Gain)

- 그룹 취향과 지역, 이전 장소의 문맥이 후보 순위에 반영되어 같은 지역 안에서도 입력에 따라 다른 장소를 낸다.
- DB에 없는 장소는 생성되지 않고, 로그에 없던 장소도 이름·유형이 비슷하면 후보가 된다.
- 회피조건, 영업·평점 하한, 슬롯 제약이 후보 제한으로 구조적으로 지켜진다.
- 결정론이므로 입력별 결과를 테스트하고 평가할 수 있다.

### Negative (Loss)

- 규칙 대비 우월성이 입증되지 않았다. 평가를 통과해야 Accepted가 된다.
- 학습 신호가 서비스 설문이 아닌 여행 로그이고, 개인 취향 → 그룹 점수 가정이 검증되지 않는다.
- 취향 입력이 0/1(4개 카테고리)이라 강도 정보가 없고 FOOD 차원이 없다. 미매핑 미션은 무시한다(정답에 노이즈).
- 로그와 DB의 정렬 품질이 측정 전이다. 코드가 어긋나면 로그의 이동 패턴이 DB 장소에 적용되지 않는다.
- 학습 규모가 선례보다 작아 과소·과적합 위험이 있다.
- 평점·평가 수 정렬이 사라져서 순위 품질이 보장되지 않고, 로그의 인기 편향(상위 1% 이름이 방문의 32.3%)이 그대로 학습될 수 있다.
- 운영 대상이 늘어난다(모델 산출물, 코드 사전, 양자화기의 버전 관리).

## Compliance / Reconsideration Conditions

**결정사항 반영 여부 검증 기준**

- [ ] 자동: 모델 출력에 대해 4개 invariant(5~6개, 2·5번째 FOOD, 회피 type 없음, 중복 없음)를 7,680건 조합 테스트로 확인한다.
- [ ] 자동(제안, 미구현): 요청 경로에서 임베딩 API 호출을 금지하는 검사를 CI에 추가한다.
- [ ] 수동: ADR-0005의 최종 평가(지역별 판정 가능한 지역 모두에서 규칙 기준선 대비 비열세, 전체에서 우세)를 통과한 뒤 Accepted로 전환한다.

**결정사항 반영 여부 측정 목록**

- [ ] 규칙 파이프라인 대비 장소 단위 Recall, 코드 접두사 적중률, 카테고리 일치도
- [ ] 연속 거리(로그 값과 규칙 값 비교), 인기순 기준선 대비 고유 장소 수와 상위 장소 집중도
- [ ] 로그·DB 정렬 일치율과 양자화 충돌 수
