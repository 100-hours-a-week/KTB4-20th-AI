# ADR-0016: place-selection의 모델 경로 실패를 폴백 없이 HTTP 503(또는 500) 에러로 반환

## Status

Proposed

1. Proposed: 2026-11-09

ADR-0010의 결정 중 "모델 호출이 실패하거나 결과가 유효하지 않으면 그 안만 규칙 변형으로 채우는 폴백을 유지한다"는 부분만 대체한다. 2·3안을 항상 모델 경로로 만들고 `PLACE_SELECTION_MODE`를 제거한 부분은 그대로다.

## Context

- ADR-0010은 모델 호출 실패 시 그 안만 규칙 변형(K=10)으로 채우는 폴백을 유지하기로 했고, 폴백 제거(오류 503)는 "GPU 장애가 곧 일정 생성 실패가 된다"는 이유로 선택하지 않았다.
- 부하 테스트 브랜치(`perf/load-test-server-tuning`, PR #122)는 개선 전후를 같은 기준으로 비교하려고 baseline을 단순화하면서(커밋 `4fca88d`, `5ede392`) 아래를 제거했다.
  - 모델 경로 실패 시 규칙 변형으로 채우는 폴백: 어느 안에서 예외가 나도 그대로 전파한다.
  - GPU 실패 후 CPU 추론: `InferenceUnavailable`을 전파한다.
  - 모델 호출 서킷 브레이커(연속 3회 실패 시 60초 차단).
- 폴백이 있으면 RunPod 호출 실패가 200 응답으로 가려져, 처리량과 실패 지점을 측정할 수 없었다.
- 같은 PR이 줄 세우기를 넣었다(`FifoGate`, 줄 상한 15, 대기 상한 55초). 줄이 가득 차거나 대기 상한을 넘으면 규칙 안으로 응답하지 않고 503을 반환한다.
- 측정값: RunPod 워커 1개 직렬 처리로 요청당 서비스 시간 최대 3.65초, 콜드 스타트 6.25~21.48초. 호출이 RunPod `/runsync` 타임아웃 55초를 넘으면 실패한다.
- PR 리뷰에서 "폴백이 없는데 괜찮은가"라는 질문이 나왔고, 사용자가 이 동작을 운영에도 반영하기로 했다(2026-11-09).
- 확인하지 못한 것: 폴백 제거를 운영에 반영하는 근거로 사용자가 든 이유(위 측정 목적 외), BE가 AI의 503(또는 500)을 사용자에게 어떻게 전달하는지, 운영 RunPod 실패 빈도.

## Decision

우리는 place-selection에서 모델 경로(RunPod 호출, 안 [1]·[2] 생성)가 실패하면 예외를 전파하여 HTTP 503(또는 500) 에러를 반환한다. 폴백은 아래 네 곳 모두 두지 않는다.

1. 모델 경로 실패 시 규칙 변형 채우기
2. GPU 실패 후 CPU 추론
3. 모델 호출 서킷 브레이커
4. 줄 가득 참·대기 초과 시 규칙 안 응답(503만 반환)

## Alternative / Considered Options

### 1. ADR-0010의 폴백 유지

- (장점) GPU 장애, 콜드 스타트, 타임아웃에도 3개 안이 항상 나온다.
- (단점) 실패가 200으로 가려져 로그(WARNING)를 찾아야만 드러나고, 처리량과 실패 지점을 측정할 수 없다.
- (소결) 선택하지 않았다. 사용자가 폴백 제거를 운영에도 반영하기로 했다.

### 2. 부하 테스트 기간에만 폴백을 빼고 운영 머지 전에 복구

- (장점) 운영 동작이 ADR-0010 그대로 유지된다.
- (단점) 측정한 구조와 운영 구조가 달라져, 측정한 처리량·실패 동작이 운영에 그대로 적용되지 않는다.
- (소결) 선택하지 않았다. 사용자 결정이다.

## Consequences

### Positive (Gain)

- 모델 경로 실패가 응답 코드로 드러나고, 규칙 결과가 모델 결과로 오인되지 않는다.
- 측정한 구조와 운영 구조가 같아, 부하 테스트 수치(줄 상한 15, 대기 55초)가 운영에 적용된다.
- 코드가 단순해진다(폴백, CPU 경로 호출, 서킷 브레이커 제거).

### Negative (Loss)

- RunPod 장애, 콜드 스타트 겹침, 타임아웃이 곧 일정 생성 실패(HTTP 503 또는 500)가 된다. ADR-0010이 우려했던 결과를 감수한다.
- 3개 안이 항상 나오는 성질(ADR-0010)이 사라진다. 안 [0]은 규칙이라도 [1]이나 [2]가 실패하면 응답 전체가 실패한다.
- 서킷 브레이커가 없어 RunPod가 계속 실패해도 요청마다 호출한다.
- 콜드 스타트가 겹치면 줄 뒤쪽 요청이 55초를 기다린 뒤 503을 받는다(계산, 미측정).
- BE가 AI의 503(또는 500)을 사용자에게 어떻게 전달하는지 확인하지 못했다.
- 이 PR 외에 폴백을 전제하는 문서가 남아 있다(`docs/trips/place-selection-evolution.md`, ADR-0010 본문). ADR은 수정하지 않으므로 이 ADR이 최신 결정이다.

## Compliance / Reconsideration Conditions

**결정사항 반영 여부 검증 기준**

- [ ] 자동: 모델 경로 예외가 규칙 변형으로 채워지지 않고 전파되는지 확인하는 테스트가 있다(`tests/test_place_selection_route.py`, `tests/test_model_serving.py` 등 해당 테스트의 통과).
- [ ] 수동: BE가 AI의 503(또는 500)을 받았을 때 사용자 화면의 동작을 클라우드·BE 팀과 확인한다.

**결정사항 반영 여부 측정 목록**

- [ ] 운영에서 place-selection의 503·500 비율. 모델 경로 실패나 콜드 스타트 겹침으로 비율이 높으면 폴백 도입을 다시 검토한다.
- [ ] RunPod 콜드 스타트 발생 횟수(Metrics 탭). 줄 뒤쪽 요청이 55초 후 503이 되는 빈도의 근거로 쓴다.
