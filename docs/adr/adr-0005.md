# ADR-0005: 장소 선정 모델의 학습 데이터와 평가를 AI-Hub 여행로그의 여행자 단위 분할로 구성

## Status

Accepted

1. Proposed: 2026-10-14
2. Accepted: 2026-10-16 (M1 구현 PR #75 머지, 분할·누수 방지 테스트 통과. 승인은 모델의 평가 결과와 무관하다)

## Context

**문제**

- 서비스 설문 응답과 행동 로그가 없어서 모델을 학습하고 평가할 신호를 외부 데이터에서 가져와야 한다.
- ADR-0000은 추천 품질을 판단할 정량 평가 기준이 없다고 기록했다. ADR-0003의 모델이 규칙을 대체할 만한지 판단하는 기준이 필요하다.

**조건과 규모 (확인된 사실)**

- AI-Hub 국내 여행로그는 4개 권역(수도권·동부권·서부권·제주) Training·Validation이다. 방문 184,719건, 방문 기록이 있는 여행 16,000건 중 여행 메타(미션)가 있는 것은 14,400건이다.
- Validation은 별개 여행자 집단이 아니라 같은 여행의 방문 일부다. 권역별로 Validation 여행의 거의 전부가 Training의 같은 여행 ID에 있고 방문 행은 겹치지 않는다.
- 방문 만족도·재방문 의향·추천 의향은 방문 단위로 있다. 만족도 있는 방문 133,523건 중 세 값이 모두 4 이상인 것은 90,607건(67.9%)이고, 만족도 단독 4 이상은 83.5%다.
- 취향에 해당하는 사전 선언 필드는 여행 미션 코드 21종이다. FOOD에 대응하는 코드가 없고, 가장 빈번한 코드 22(SNS 인생샷)를 포함해 일부는 5개 서비스 카테고리에 대응되지 않는다.
- 서비스 지역으로 한정한 학습 가능 하루 시퀀스는 12,870개(서울 3,403, 부산 1,071, 제주 7,237, 전주 505, 경주 654)다.
- 로그에는 점심·저녁 위치 패턴이 없다. 식당/카페 비율이 위치별로 0.30~0.39로 평평하다.

**가정 (확인되지 않음)**

- 미션 코드가 여행 전에 정해진 선호를 반영한다.
- 개인 여행자의 취향으로 학습해도 그룹 점수 입력에 작동한다.

## Decision

우리는 AI-Hub 국내 여행로그로 학습하고, 여행자 단위 분할과 한 번만 보는 최종용 평가로 규칙 기준선과 비교해 대체 여부를 판단한다.

- 데이터: Training과 Validation을 합쳐 여행을 온전히 만든다. 집·숙소를 제외한 방문으로 하루(`TRAVEL_ID` + 방문일) 단위 시퀀스를 만들고, 서비스 5개 지역으로 한정한다.
- 정답 신호: 만족도·재방문 의향·추천 의향이 모두 4 이상인 방문이다.
- 취향 입력: 여행 미션 코드를 4개 카테고리(HISTORY_CULTURE, NATURE_HEALING, ACTIVITY, CONVENIENCE_SHOPPING)의 0/1로 변환한다. 매핑되지 않는 코드는 무시하고, 4개 카테고리가 모두 0인 여행은 학습에서 뺀다. 방문 행동으로 취향을 만들지 않는다(정답 누수).
- 분할: 여행자 단위 학습 70% / 개발 15% / 최종 15%. 분할은 한 번만 생성해 덮어쓰지 않고, 최종용은 한 번만 열람한다.
- 합격 지표: 장소 단위 Recall@10 하나로 판정한다. 분모는 DB 장소에 대응된 모든 정답 방문이고 품질 필터(영업 중, 평점 3.0 초과, 평가 수 10 이상) 통과 여부와 무관하다. 필터에 막힌 방문(개발용 대응 방문의 28.4%, 2026-10-16 측정)은 상한을 낮추지만 규칙과 모델에 똑같이 적용된다.
- 보고 지표: Recall@1·5, 코드 접두사 적중률(전체 방문), 카테고리 일치도, 연속 거리, 고유 장소 수, 상위 장소 집중도, 필터에 막힌 방문 비율(지역별). 합격 판정에 쓰지 않는다. 4개 invariant 통과율은 지표가 아니라 전제 조건이며 100%여야 한다.
- 비교: 합격 비교 대상은 규칙 파이프라인이고, 인기순은 하한 점검용이다. CatBoost 점별 회귀는 기한(2026-10-19~20) 때문에 이번 범위에서 생략하고 보고서에 "미실시"로 적는다. 같은 분할에서 같은 날에 대한 대응 비교를 하며, 규칙의 무작위성은 시드 10개의 평균으로 줄인다. 신뢰구간은 여행자 단위 묶음 부트스트랩(95%)으로 구한다.
- 비열세 마진: 개발용에서 측정한 규칙 기준선 Recall@10의 10%(상대값)이다. 개발용 측정값은 2.448%이므로 마진은 0.245%p로 기록한다(2026-10-16, 최종용을 열기 전).
- 지역별 판정(비열세 검정): 최종용에서 모델과 규칙의 Recall@10 차이의 95% 신뢰구간(여행자 단위 묶음 부트스트랩)이 하한 > −마진이면 비열세 통과, 상한 < −마진이면 불합격, −마진을 걸치면 보류한다. 일수가 100일 미만이라는 이유로, 또는 개발용 신뢰구간 폭만으로는 보류하지 않는다. 보류 지역은 최종용 Recall을 보고만 하고 판정에서 제외한다.
- 최종용 평가 결과(2026-10-16, 1회 실행, 모델 A, 빔 폭 10, 정답 방문 5,856건, 여행자 1,003명): Recall@10은 모델 13.8%, 인기순 5.9%, 규칙 2.5%이다. 모델 − 규칙 차이의 95% 구간은 서울 +12.0~+15.6%p, 부산 +16.8~+23.8%p, 제주 +5.8~+7.8%p, 경주 +14.8~+24.2%p, 전주 +23.1~+35.9%p로 하한이 모두 −마진(−0.245%p)보다 커서 5개 지역 모두 통과했고 판정된 지역은 전체 방문의 100%이다. 전체 모델 − 규칙은 +11.4%p(+10.5~+12.3), 모델 − 인기순은 +7.9%p(+7.0~+8.8)이다. 정답 중 후보 안에 있는 비율(상한)은 57.4%이다. 결과 파일은 레포 밖 `m3/eval/final_model_a.json`.
- 개발용 예상 판정(2026-10-16, 모델 A 3.37M, 빔 폭 10, 정답 방문 5,780건): Recall@10은 모델 13.4%, 인기순 5.5%, 규칙 2.4%이다. 지역별 모델 − 규칙 차이의 95% 구간은 서울 +12.2~+15.6%p, 부산 +16.5~+23.6%p, 제주 +5.9~+7.9%p, 경주 +10.3~+18.5%p, 전주 +18.0~+31.5%p로 하한이 모두 0보다 크다. 따라서 5개 지역 모두 통과가 예상되며 판정 가능 지역은 전체 방문의 100%로 예상한다. 이는 예상일 뿐이며 판정은 최종용 결과로 한다. 전체에서는 모델 − 규칙이 +10.9%p(+10.0~+11.8), 모델 − 인기순이 +7.9%p(+6.9~+8.7)이다.
- 대체 판단: 판정 가능 지역(통과 또는 불합격으로 판정된 지역)이 전체 방문의 80% 이상이고, 그 지역 모두에서 비열세이고 전체에서 우세하면 대체한다. 보류 지역은 최종용 결과가 나온 뒤에야 확정된다. 지역별로 모델과 규칙을 나눠 쓰는 도입은 하지 않는다(전부 아니면 전무).

## Alternative / Considered Options

### 1. 방문 행동으로 취향 벡터를 계산

- (장점) 연속값 강도와 FOOD 차원을 만들 수 있다.
- (단점) 같은 여행의 방문으로 취향을 만들면 정답이 입력에 섞이고(누수), 다른 날 방문을 쓰면 24.5%의 하루에는 만들 수 없다. 방문지 분류기가 필요한데 POI 분류가 12.6%만 채워져 있다.
- (소결) 선택하지 않았다.

### 2. AI-Hub 기본 Training/Validation 분할을 그대로 사용

- (장점) 공식 분할이라 재현이 쉽다.
- (단점) 같은 여행이 양쪽에 걸쳐 평가가 부풀려진다.
- (소결) 선택하지 않았다.

### 3. 여행 단위 분할 (여행자 단위가 아님)

- (장점) 단순하다.
- (단점) 같은 여행자의 다른 여행이 학습에 들어가 취향 프로필이 새어 들어갈 수 있다.
- (소결) 여행자 단위를 선택했다. 전체 데이터에서는 여행 14,400건과 여행자 14,400명이 1:1이라 실제 분할 결과는 여행 단위와 같다. 여행자 단위로 정의한 것은 같은 여행자가 여러 여행을 가진 데이터가 들어올 때 누수를 막기 위한 안전장치다.

### 4. 만족도 단독 4 이상을 정답으로 사용

- (장점) 데이터가 가장 많이 남는다.
- (단점) 만족도 있는 방문의 83.5%가 통과해 거의 걸러지지 않는다.
- (소결) 선택하지 않았다.

### 5. 장소 단위 Recall만 사용

- (장점) 정확한 지표다.
- (단점) 로그 방문의 82.5%는 DB 장소와 대응되지 않아 표본이 17.5%로 줄어든다.
- (소결) 코드 접두사 적중률을 함께 쓴다.

## Consequences

### Positive (Gain)

- 취향 입력이 여행 전에 정해진 값이어서 누수가 없고 서비스 설문과 성격이 같다.
- 최종용을 한 번만 보므로 규칙 대체 판단의 근거가 된다.
- 지역별 판정 보류 기준으로 표본이 작은 지역의 과대 해석을 막는다.

### Negative (Loss)

- 여행 로그와 서비스 설문은 도메인이 다르다. 미션이 선택형인지 과제로 주어진 것인지 확인되지 않았다.
- 취향 입력이 0/1이라 강도가 없고 FOOD 차원이 없으며, 21종 중 5종(시티투어 포함)이 무시된다.
- 서비스 5개 지역으로 한정하면 학습 문제가 45,146개이고, 경주·전주는 개발용 기준 여행자가 73명·57명이어서 신뢰구간이 넓어 보류될 수 있다.
- 정렬 검증 쌍이 이름 유사도로 선택되어 이름 기반 임베딩에 유리한 편향이 있을 수 있다.
- 일치 대응이 17.5%라 장소 단위 Recall은 표본이 작다.

## Compliance / Reconsideration Conditions

**결정사항 반영 여부 검증 기준**

- [ ] 자동: 분할 결과에서 한 여행자가 두 몫에 걸치지 않는지, 같은 시드로 같은 분할이 나오는지 확인하는 테스트
- [ ] 자동: 학습 예제 생성에서 취향 벡터가 미션 코드만으로 계산되는지(방문 행동을 쓰지 않는지) 확인하는 테스트
- [ ] 수동: 최종용 평가를 한 번만 실행했다는 기록을 남긴다.

**결정사항 반영 여부 측정 목록**

- [ ] 지역별 개발용 신뢰구간 폭(여행자 단위 묶음 부트스트랩)과 판정 가능 지역의 방문 비중
- [ ] 학습 규모가 부족할 때 서비스 지역 밖 데이터를 포함한 실험 결과
- [ ] 서비스 설문 응답이 쌓인 뒤 취향 변환 기준의 재보정 결과
