# ADR-0011: 1안을 평점 정렬 상위 10곳 중 요청 기반 시드로 선택

## Status

Proposed

1. Proposed: 2026-10-21

ADR-0008의 결정 중 1안(`places[0]`)을 "후보 앞에서부터 평점순으로 채운다"고 정의한 부분만 바꾼다. 2·3안의 구성은 ADR-0010을 따른다. 백엔드(Spring)가 1안을 평점순 상위로 가정하는지 확인하기 전에는 Accepted로 바꾸지 않는다.

## Context

- 1안은 규칙 경로로 만든다. DB가 `rating × 0.6 + LOG(평가 수 + 1) × 0.4` 내림차순으로 정렬한 후보에서, 이미 쓴 장소를 건너뛴 첫 장소를 슬롯마다 고른다. 시드가 없고 무작위도 없어서 같은 요청은 항상 같은 1안이다(`variant_seed`가 `None`이면 `pick_width`가 1).
- 2·3안의 규칙 변형(모델 경로 실패 때 폴백)은 같은 정렬의 상위 K=10곳 중 시드로 고른다(`RULE_VARIANT_TOP_K = 10`, 잠정값).
- ADR-0008은 1안을 "Spring이 재정렬해 최단 거리 안으로 쓰는 원본"이라고 정의했다. 설계 로그는 "규칙 `[0]`을 항상 평점순 1개로 두는 것이 Spring의 재정렬 요구에 충분한지 확인하지 못함"으로 남겼고, 지금도 확인하지 못했다.
- 모델 경로는 이미 첫 장소를 모델 상위 30곳 중 시드로 고른다(ADR-0007). 규칙 경로의 1안만 입력이 같으면 항상 같은 장소를 낸다.
- 안 사이 겹침 측정(ADR-0008): 2안 대 1안 418/420일, 3안 대 1안 419/420일이 일자당 2곳 이상 달랐다. 이 측정은 1안이 시드 없는 평점순일 때의 값이다.

## Decision

우리는 1안을 평점 가중 정렬 상위 K=10곳 중에서 요청 기반 시드로 고른다. 시드는 안마다 다르게 파생한다(`plan0`, 2안과 3안의 규칙 변형은 각각 `plan1`, `plan2`). 시드 입력, 후보 품질 하한, 날씨 제외, 여행 전체 중복 제거는 그대로다.

## Alternative / Considered Options

### 1. 시드 없이 평점순을 그대로 유지

- (장점) Spring이 평점순 상위를 가정해도 안전하고 백엔드 협의가 필요 없다. 안 사이 겹침 측정을 그대로 쓸 수 있다.
- (단점) 입력이 같으면 항상 같은 1안이다. 규칙 변형(K=10)과의 일관성이 없다.
- (소결) 선택하지 않았다. 사용자가 규칙 변형 방식을 1안에 적용하기로 했다. 백엔드 확인에서 평점순이 필요하다고 나오면 이 대안으로 돌아간다.

### 2. 첫 슬롯만 평점 정렬 상위 30곳 중 시드로 고르고 나머지는 1위 순서로 채움

- (장점) 모델 경로의 첫 장소 무작위(ADR-0007, K=30)와 같은 구조라 1안이 평점순에서 덜 벗어난다.
- (단점) 규칙 경로에 새 로직이 필요하고 지금 코드에 없다. 사용자가 선택하지 않았다.
- (소결) 선택하지 않았다.

## Consequences

### Positive (Gain)

- 1안도 요청이 다르면 다른 장소 조합이 나온다. 규칙 경로 전체가 하나의 선택 방식(상위 K곳 중 시드)으로 통일된다.
- 코드 변경이 한 곳(1안 호출에 시드 전달)이라 되돌리기 쉽다.

### Negative (Loss)

- Spring이 1안을 평점순 상위로 가정하는지 확인하지 못했다. 가정이 맞다면 재정렬 결과가 달라진다.
- 1안이 평점 상위 1위가 아니라 상위 10곳 중 하나가 되므로 "평점 최고" 보장이 사라진다.
- 안 사이 겹침 측정(418/420일, 419/420일)이 1안이 바뀐 뒤의 값과 비교할 수 없다. 다시 재야 한다. 1안과 2·3안이 같은 후보 집합에서 시드로 고르므로 겹침이 늘 수 있고, 이 효과는 측정하지 못했다.
- 같은 요청은 같은 1안이다(시드가 요청 해시에서 나옴). 재생성 요청이 같은 일정을 돌려주는 한계(ADR-0007)는 풀리지 않는다.
- 규칙 경로의 DB 조회 한도가 `슬롯 수 + 1 + 여유`에서 `슬롯 수 + 10 + 여유`로 커진다.
