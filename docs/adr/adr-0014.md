# ADR-0014: 사람 평가를 층화 추출한 요청의 절대 평가 80%와 이름을 가린 쌍 비교로 구성

## Status

Proposed

1. Proposed: 2026-10-28

## Context

- ADR-0013이 운영 반영 판정에 일정의 사용 가능성을 직접 확인하는 평가를 요구한다. 로그 정답으로는 이를 재지 못한다(Recall@10은 과거 방문과의 유사도).
- 규칙이 같은 요청에 더 나은 일정을 낸다면 모델 경로를 올릴 이유가 없다. 모델 경로에는 GPU 비용과 콜드 스타트가 따른다.
- 학습 일수는 지역별로 제주 7,237, 서울 3,403, 부산 1,071, 경주 654, 전주 505다. 무작위로만 뽑으면 작은 지역이 한두 개로 줄 수 있다.
- 평가에 참여할 사람과 일정은 정해지지 않았다. 기한이 임박해 규모 있는 설문은 어렵다.

## Decision

우리는 팀원이 일정을 직접 보는 사람 평가를 절대 평가와 쌍 비교로 하고, 둘 다 통과해야 한다.

- 요청: 지역 5 × 일수(1일 / 여러 날)로 층을 나눠 시드를 정해 층마다 2~3개, 모두 20~30개를 뽑는다. 요청 목록과 시드는 평가 전에 파일로 고정한다.
- 평가자: 팀원 2~3명이 같은 세트를 모두 본다. 가능하면 모델 개발에 직접 참여하지 않은 팀원을 포함하고 평가자 일치도를 함께 보고한다. 참여자와 일정은 미정이다.
- 절대 평가: 모델 일정을 보고 "그대로 여행에 쓸 수 있는가"를 예/아니오로 표시한다. 예가 80% 이상이어야 통과다. 80%는 측정이나 선행 사례가 없는 임의값이다(평가자 판단 차이로 20% 정도가 떨어질 수 있다는 판단).
- 쌍 비교: 같은 요청의 모델 일정과 규칙 일정을 이름을 가려 보여 주고 "모델이 낫다 / 규칙이 낫다 / 비슷하다"를 고른다. 모델 우세 쌍이 규칙 우세 쌍 이상이어야 통과다.
- 구현 범위: 요청 목록을 뽑는 스크립트와 이름을 가린 시트까지 만든다. 응답 수집은 스프레드시트에 직접 표시한다.

## Alternative / Considered Options

### 1. 사람 평가 없이 규칙 검사만

- (장점) 재현이 쉽고 빠르다.
- (단점) 결함이 없다는 것만 말하고 사용자가 쓸 만하다고 느끼는지, 규칙보다 나은지는 알 수 없다.
- (소결) 선택하지 않았다.

### 2. 외부 사용자나 지인까지 모은 설문

- (장점) 표본이 크고 실제 사용자에 가깝다.
- (단점) 기한 안에 현실적이지 않다.
- (소결) 선택하지 않았다.

### 3. 쌍 비교를 확장 항목으로만 두기

- (장점) 평가 부담이 작다.
- (단점) 규칙보다 못하면 올리지 않는다는 ADR-0013의 조건을 확인하지 못한다.
- (소결) 선택하지 않았다. 쌍 비교는 필수다.

## Consequences

### Positive (Gain)

- 일정의 사용 가능성과 규칙 대비 우열을 사람이 직접 확인한다.
- 요청 목록 고정과 이름 가림으로 결과에 맞춘 선택을 막는다.

### Negative (Loss)

- 표본이 20~30개라 통계적 결론이 아니며 "확인한 범위에서"만 주장한다. 30개 중 24개가 예일 때 80%의 95% 신뢰구간이 대략 61~92%다.
- 평가자가 모델 개발과 가까우면 호의적일 수 있다.
- 참여자와 일정이 정해지지 않았다.

## Compliance / Reconsideration Conditions

**결정사항 반영 여부 검증 기준**

- [ ] 수동: 요청 목록과 시드가 평가 전에 파일로 고정되어 있다.
- [ ] 수동: 평가 시트에서 일정이 모델/규칙 표시 없이 제시되었다.

**결정사항 반영 여부 측정 목록**

- [ ] 평가자별 예 비율, 평가자 일치도, 쌍 비교 결과(모델 우세 / 규칙 우세 / 비슷)
- [ ] 지역별 요청 수
